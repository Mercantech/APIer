Dependency Injection og services

ASP.NET Core leverer et indbygget DI-container. I registrerer abstraktioner i Program.cs og får dem ind i komponenter via @inject — så Pokémon-lister, LoL-champions og auth håndteres i testbare services.

Læringsmål

  • Fortælle hvad DI løser (løs kobling, testbarhed, central konfiguration).
  • Vælge mellem Transient, Scoped og Singleton med begrundelse.
  • Registrere HttpClient via IHttpClientFactory og typed clients mod OpgaverAPI.
  • Strukturere services (interface + implementation) og undgå «service locator»-antipattern.

Når en Blazor-side skal hente Pokémon fra /go/pokemon og champions fra LoL med X-Api-Key, hører HTTP-logikken ikke hjemme direkte i markup. I opretter fx IPokemonService og ILolService, registrerer dem én gang, og injicerer dem i komponenter — samme idé som i et ASP.NET Web API-projekt.

Program.cs — registrering

I en Blazor Web App er Program.cs composition root: her tilføjer I render modes, Razor Components, og alle services.

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddRazorComponents()
    .AddInteractiveServerComponents();

// Base URL til OpgaverAPI (miljøspecifik i Docker/Dokploy)
var apiBase = builder.Configuration["OpgaverApi:BaseUrl"]
    ?? "https://api-opgaver.mercantec.tech";

builder.Services.AddHttpClient<IPokemonService, PokemonService>(client =>
{
    client.BaseAddress = new Uri(apiBase);
});

builder.Services.AddScoped<ILolService, LolService>();
builder.Services.AddSingleton<IApiKeyStore, SessionApiKeyStore>();

var app = builder.Build();
// … middleware, MapRazorComponents, Run

AddHttpClient<TClient, TImplementation> kombinerer DI med en korrekt konfigureret HttpClient (handler-pool, DNS, timeouts). Det er Microsofts anbefalede vej — ikke new HttpClient() i hver komponent.

@inject i komponenter

@page "/pokemon-di"
@inject IPokemonService Pokemon

<h1>Pokémon</h1>
@if (loading) { <p>Henter…</p> }
else if (error is not null) { <p class="err">@error</p> }
else
{
  <ul>@foreach (var p in list!) { <li>@p.Name</li> }</ul>
}

@code {
  List<PokemonDto>? list;
  bool loading;
  string? error;

  protected override async Task OnInitializedAsync()
  {
    loading = true;
    try { list = await Pokemon.GetFirstAsync(24); }
    catch (Exception ex) { error = ex.Message; }
    finally { loading = false; }
  }
}
public interface IPokemonService
{
    Task<List<PokemonDto>> GetFirstAsync(int limit, CancellationToken ct = default);
}

public sealed class PokemonService(HttpClient http) : IPokemonService
{
    public async Task<List<PokemonDto>> GetFirstAsync(int limit, CancellationToken ct = default)
    {
        var url = $"/go/pokemon?limit={limit}";
        return await http.GetFromJsonAsync<List<PokemonDto>>(url, ct)
            ?? throw new InvalidOperationException("Tomt svar");
    }
}

public record PokemonDto(string Name, int Id);

Lifetimes — hvornår hvad?

LifetimeBetyderTypisk brug i Blazor
TransientNy instans hver gang den anmodesLette, stateless helpers (formatters, validators uden state)
ScopedÉn instans pr. scope (ofte pr. HTTP-request / circuit på Server)Services der cacher per bruger-session, DbContext-lignende state
SingletonÉn instans for hele appenRead-only config, caches med thread-safety, IHttpClientFactory selv

# Vælg lifetime og tryk Anmod

Faldgrube: At registrere DbContext eller bruger-specifik state som Singleton deler data mellem alle brugere. At registrere HttpClient som Singleton uden factory kan give socket-udmattelse — brug IHttpClientFactory.

IHttpClientFactory og typed client

Typed clients er klasser der tager HttpClient i konstruktoren og kapsler endpoints. Factory’en håndterer levetid af handlers.

builder.Services.AddHttpClient<ILolService, LolService>(client =>
{
    client.BaseAddress = new Uri(apiBase);
    client.DefaultRequestHeaders.Add("Accept", "application/json");
});

// I LolService tilføjes X-Api-Key per kald fra IApiKeyStore — ikke hardcodet i git

Hvis I både har WASM og Server i samme solution, kan base URL komme fra appsettings.json + miljøvariabler i Docker — præcis som APIer-projektets compose-mønster.

Interfaces og test

Med IPokemonService kan I i en unit test mocke API’et og teste komponentlogik uden netværk. Det er sværere hvis komponenten kalder Http.GetFromJsonAsync direkte overalt.
