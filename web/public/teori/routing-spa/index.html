Routing og SPA

Flere «sider» i én Blazor-app med routing, deep links, query strings og NavLink — SPA uden fuld page reload.

Læringsmål

  • Definere routes med @page og flere stier per komponent.
  • Bruge NavLink til aktiv markering i NavMenu.
  • Læse query parameters (?name=pikachu) med [SupplyParameterFromQuery].
  • Forklare deep linking og fordele/ulemper ved SPA.

En SPA loader shell én gang. Blazor router matcher URL til komponent, skifter indhold i @Body, bevarer layout og DI-scope (afhængigt af hosting).

SPA uden page-reload

Klik i «navbaren» — kun midterindholdet skifter. Shell (layout) bliver.

Velkommen

MainLayout + NavMenu omslutter alle sider.

@page "/pokemon"

HttpClient henter data — URL skifter, ingen fuld reload.

@page "/status"

Deep link kan deles — samme app i hukommelsen.

@page "/pokemon"
@page "/dex"
@layout MainLayout

<PageTitle>Pokédex</PageTitle>
<h1>Pokémon</h1>

NavLink

<NavLink class="nav-link" href="pokemon" Match="NavLinkMatch.Prefix">
  Pokémon
</NavLink>
<NavLink class="nav-link" href="lol">
  LoL
</NavLink>

Match="All" (default) kræver præcis path; Prefix matcher understier.

Query parameters

@page "/soeg"

<p>Søger efter: @name</p>

@code {
  [SupplyParameterFromQuery]
  public string? Name { get; set; }

  protected override async Task OnParametersSetAsync()
  {
    if (!string.IsNullOrWhiteSpace(Name))
      await SearchAsync(Name);
  }
}

URL /soeg?name=charizard kan bookmarkes og deles — god UX til API-søgning.

Route parameters

@page "/pokemon/{id:int}"

<h1>Detail #@Id</h1>

@code {
  [Parameter] public int Id { get; set; }
}

Layouts

MainLayout.razor indeholder fælles chrome; sider sætter @layout eller arver default fra Routes.razor.

Faldgrube: At bruge plain <a href> uden Blazor router — fuld reload, tab af circuit state på Server. Brug NavLink eller NavigationManager.

Fordele SPA: hurtig navigation, genbrug af services/state, én codebase.
Ulemper: større initial load (især WASM), SEO kræver plan, auth tokens håndteres i klient.
